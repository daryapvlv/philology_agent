# Структура книги: секции, сцены и правки

Структура строится при импорте (оглавление EPUB / заголовки Markdown), дальше
правится вручную в интерфейсе. Рабочее хранилище — Neo4j, через `BookService`.
Сцены строятся отдельно для `body` выбранной главы. Поиск, чанки и эмбеддинги —
в отдельном модуле [`retrieval`](../retrieval/README.md); загрузка и парсинг
исходного файла — в [`ingest`](../ingest/README.md).

## Подключение

Нужна Neo4j 5.26+. Переменные — в [.env.example](../.env.example)
(`NEO4J_URI`/`NEO4J_USERNAME`/`NEO4J_PASSWORD`/`NEO4J_DATABASE`); `.env` не
загружается автоматически:

```sh
set -a && source .env && set +a
.venv/bin/python -m structure.cli.graph check
```

Без подключения к Neo4j показывается ошибка; общий чат без книги остаётся
доступен.

## Работа в интерфейсе

Подтверждение относится только к структуре книги (произведения/главы/разделы) —
построение и правки сцен его не сбрасывают. Порядок: проверить структуру во
вкладке «Разметка» → построить/обновить сцены выбранной главы → при необходимости
отредактировать сцену (название, описание, разделение, объединение соседних,
перенос границы; координаты — символы канонического текста книги).

Смена границ главы помечает её сцены `stale`; изменение границ сцены помечает
её описание требующим уточнения. Ручной слой при повторном анализе сохраняется,
если явно не выбрано «Заменить ручную разметку при пересчёте».

## Модель графа

- `LiteraryBook` — канонический текст и версия записи (растёт при каждом сохранении).
- `BookSection` — раздел (произведение/глава/акт и т.п., полный список ролей —
  в `rules/sections.py`), дерево через `CONTAINS`.
- `SectionBlock` (`epigraph`/`body`/`footnotes`) — содержимое раздела через
  `HAS_BLOCK`; `body.text` собирается без отмеченных примечаний.
- `NarrativeScene` — границы символов, название, описание; связана с `body`
  через `HAS_SCENE`. `SceneLayer` хранит статус анализа главы
  (`ready`/`partial`/`failed`/`stale`; нет слоя — `not_started`).
- `EntityMention` / `EntityReference` / `Entity` — упоминания и разрешённые
  внутри книги сущности (`HAS_MENTION`, `REFERS_TO_MENTION`, `REFERS_TO`).

Все узлы несут `book_id`; диапазоны символов — полуоткрытые `[start, end)`.
Полная схема связей и служебных полей — в `graph_db/repository.py`.

## Транзакции

Запись проверяет `expected_revision` под блокировкой узла книги и откатывается
целиком при конфликте. LLM не вызывается внутри транзакции: сцены сохраняются
по мере обработки главы, при ошибке слой остаётся частичным, а кэш не
расходует новые вызовы при повторном запуске.

## Файлы

- `application/book_service.py` — фасад операций книги для агента и UI.
- `rules/` — валидация и сборка разделов, блоков и сцен.
- `graph_db/repository.py` — Neo4j, транзакции, запросы.
- `workflows/edit_sections/`, `workflows/build_scenes/`, `workflows/edit_scenes/`.
- `frontend/book.py` — адаптер интерфейса.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
RUN_NEO4J_TESTS=1 .venv/bin/python -m unittest discover -s tests -p test_neo4j_integration.py -v
```

Второй запуск требует реального сервера: создаёт и удаляет только свои
тестовые книги (`test:` ID), проверяя импорт, идемпотентность, редактирование,
конфликты и удаление.
