# Индексация книги

`retrieval.indexing.IndexService` отвечает за подготовку поисковых данных:
проверку детерминированных фрагментов, эмбеддинги и атомарную запись в Neo4j.
`TextChunk` создаются после `NarrativeScene` и принадлежат ровно одной сцене.
Полный текст книги не изменяется: `TextChunk` получают абсолютные координаты
канонического текста, не пересекают границы сцен и нарезаются только внутри
body-диапазонов с исключением эпиграфов и примечаний.

Ограничения и fulltext indexes создаются отдельной инфраструктурной миграцией:

```sh
python -m infrastructure.neo4j.migrate
```

`IndexService.index_book()` не изменяет схему базы в runtime.

```python
from retrieval.indexing import IndexService

index = IndexService(book_id, embedder=my_configured_embedder)
stats = index.index_book(min_chars=400, max_chars=1200, batch_size=32)
```

Без embedder создаётся лексический индекс, а подходящие существующие эмбеддинги
сохраняются. Для этого режима доступен CLI:

```sh
python -m retrieval.cli.index BOOK_ID
```

Модуль загружает исходный текст из Neo4j в Python, но не передаёт его генеративной
модели. Для каждой готовой `NarrativeScene` код создаёт `TextChunk` по авторским
абзацам (`scene_chunks()`):
подряд идущие короткие абзацы — обычно реплики одного диалога — склеиваются, пока
отрывок короче `min_chars` (400); абзац длиннее `max_chars` (1200) делится по
границам предложений. Перекрытия нет. Единица поиска совпадает с единицей оценки и
цитирования: найденный отрывок — уже короткий связный фрагмент текста, а не
техническое окно. Для «Капитанской дочки» это 284 отрывка с медианой около 600
символов. Связи — `LiteraryBook-[:HAS_CHUNK]->TextChunk` и
`NarrativeScene-[:HAS_CHUNK]->TextChunk`; порядок хранится в `NEXT_CHUNK`.
Диапазоны `[start_char, end_char)` относятся к каноническому тексту, не к страницам.
Индексы слов создаются для текста фрагментов и названий/описаний существующих сцен.
Изменения сцен автоматически отражаются в полнотекстовом индексе Neo4j. При
индексации с embeddings отдельно сохраняются векторы `title + summary` актуальных
сцен; semantic retrieval объединяет их с text-каналом через RRF.

## Подключение эмбеддингов

Провайдер реализует `Embedder` из `retrieval.indexing`:

```python
class MyEmbedder:
    model = 'provider/model-version/dimensions'

    def embed_documents(self, texts: list[str]) -> list[list[float]]:
        ...  # вернуть векторы в том же порядке

    def embed_query(self, text: str) -> list[float]:
        ...  # используется retrieval.search_semantic
```

Это контракт адаптера. Готовый OpenAI-совместимый клиент находится в
`retrieval/embeddings.py`: `configured_embedder()` читает EMBEDDING_MODEL,
EMBEDDING_API_KEY и EMBEDDING_BASE_URL. Агент использует его автоматически;
для отдельной подготовки доступен `python -m retrieval.cli.index BOOK_ID --embeddings`.
Свой адаптер также можно передать в `IndexService` и `SearchService`. Меняйте `model` при
смене модели, размерности или настроек подготовки текста. Документы и запросы могут
использовать разные режимы кодирования внутри адаптера.

Индексация с embedder может быть платной. Эмбеддинги кешируются в Neo4j по хешу текста
и имени модели: повторная индексация неизменившейся книги возвращает
`embedded_texts=0`. Правки глав и сцен не требуют пересчёта эмбеддингов текста.
Смена модели пересчитывает все фрагменты. Векторы отправляются в базу вместе с
фрагментами одной атомарной записью; при сбое до записи новый embedding-результат
не сохранится, прежний индекс останется доступен. Вызовы провайдера идут вне
транзакции, по 32 текста за раз. Конкурирующее изменение книги/индекса отменяет
запись с `ConflictError`.

## Хранилище и совместимость

Запись индекса сосредоточена в `retrieval/indexing/repository.py`; снимки
исследований хранит SQLite-адаптер `infrastructure/sqlite/search_sessions.py`.
Удаление книги удаляет её `TextChunk`; исследования удаляются вместе с локальным чатом. Имена существующих индексов
`retrieval_text`, `retrieval_scenes`, `retrieval_chunk_id` сохранены, поэтому
из-за переноса кода переиндексация и миграция данных не требуются.

Проект ориентирован на Neo4j 5.26+. Нужны права создания ограничений и индексов.
Готовность каждого полнотекстового индекса ожидается до 60 секунд. Используются
[полнотекстовые индексы Neo4j](https://neo4j.com/docs/cypher-manual/5/indexes/semantic-indexes/full-text-indexes/)
и [vector.similarity.cosine](https://neo4j.com/docs/cypher-manual/5/functions/vector/).
Семантический индекс описаний сцен пока не создаётся.
